# The Rhetoric update channel

How automated updates work, and the exact steps to push one.

## Design

- **Host:** GitHub Releases on `kingcinder/Rhetoric-TTS` ($0, no server).
- **Stable URL:** `https://github.com/kingcinder/Rhetoric-TTS/releases/latest/download/update-manifest.json`
  — GitHub resolves `latest/download/<asset>` to the newest release, so
  the app never needs a new URL baked in. The app reads the URL from one
  constant (`the_oracle.update_service.DEFAULT_MANIFEST_URL`), overridable
  with the `RHETORIC_UPDATE_MANIFEST_URL` environment variable (mirrors /
  testing).
- **Format:** manifest format 1 — `{format, version, artifacts[{name,
  sha256, size}], rollback}`, generated by
  `scripts/build_frozen_linux.py::write_update_manifest` and validated by
  the single shared core in `src/the_oracle/update_manifest.py` (the
  release checker `scripts/check_update_manifest.py` and the app import
  the same code).
- **Safety:** the app verifies each artifact's size and SHA-256 against
  the manifest *before* installing, and never applies an unverified
  artifact. AppImage installs self-apply with a `.previous` rollback
  copy kept next to the running file; a failed apply restores it. Other
  builds are told an update exists and how to get it (source checkouts:
  `./rhetoric update`).
- **Opt-out:** Settings → Advanced → "Turn off automated updates"
  (off by default, i.e. updates on). Opting out also suspends support
  submissions — see `docs/SUPPORT.md` and the warning beside the toggle.

## Pushing an update (release steps)

1. Land everything on `release/1.5.0-final`, run the full suite green,
   and run `scripts/release.py --check`.
2. Build the frozen artifacts:
   `./.venv/bin/python scripts/build_frozen_linux.py --outdir release_artifacts/linux-frozen`
   This emits the AppImage/.deb, checksums, the SBOM, and
   `update-manifest.json` covering exactly those artifacts.
3. Record the suite counts for the new head if the counts gate requires
   it (`scripts/certify_suite_counts.py --record` per the CI job).
4. Tag the release commit (e.g. `v1.5.1`) and create the GitHub release
   for that tag on `kingcinder/Rhetoric-TTS`.
5. Upload as release assets: every artifact listed in the manifest
   **and `update-manifest.json` itself**, with the exact file names from
   the manifest (the app's download URL is the manifest URL with the
   file name swapped in).
6. Verify from a machine that is not the build box:
   `curl -sL https://github.com/kingcinder/Rhetoric-TTS/releases/latest/download/update-manifest.json`
   returns the new manifest, and
   `./.venv/bin/python scripts/check_update_manifest.py <downloaded manifest> --artifact-dir <dir with artifacts> --artifact <name>`
   verifies an artifact against it.
7. Existing installs pick the release up on their next automated check
   (at launch). AppImage installs download, verify, and swap in place;
   the previous file stays as `<name>.previous` for rollback.

## Rolling back a bad release

1. Delete the bad GitHub release (or mark the previous release as
   latest again) — the stable URL immediately resolves to the older
   manifest. The app only ever moves *forward* to a newer version, so
   also publish a forward fix release as soon as possible; the rollback
   restores the channel, it does not downgrade installed copies.
2. On a machine where a bad AppImage apply already happened, replace
   the AppImage file with its `<name>.previous` sibling to restore the
   prior version manually.
